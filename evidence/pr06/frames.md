# ПР06: модель робота и дерево TF

## Исходные данные и соглашения

Источник размеров — `.course-kit/v1/models/course_ackermann/model.sdf`.
ROS-описание — `src/course_description/urdf/ackerman_robot.urdf.xacro`.
Единицы: метры, килограммы, секунды, радианы. Для звеньев при нулевых
углах сочленений X направлена вперёд, Y влево, Z вверх. Корень — `base_link`.
Внешнее размещение SDF-модели на высоте 0.18 м не переносилось во внутреннее
дерево робота; `map` и `odom` в этой работе не публикуются.

Xacro разворачивается в URDF, текст передаётся параметром `robot_description`
в `robot_state_publisher`. Launch и конфигурация RViz находятся в пакете
`course_description`. В RViz выбран Fixed Frame `base_link`.

Дерево содержит 10 звеньев и 9 соединений, связно и не содержит циклов.
База параметризована значением 0.8 м, колея — 0.62 м, радиус колеса — 0.12 м.
Ширина колеса — 0.07 м. Геометрия колёс и исходная система тензора инерции
повёрнуты на pi/2 вокруг X внутри link; этот поворот не нужно повторять в joint.
Рулевые углы ограничены диапазоном [-0.55, 0.55] рад. Предел скорости руления
1 рад/с — отмеченное в модели настраиваемое допущение, отсутствующее в SDF.

Камера, лидар и IMU представлены звеньями с инерцией и фиксированными
соединениями. У них нет собственной visual-геометрии, как и у исходных SDF-звеньев.
Симуляционные блоки sensor и плагины Gazebo в URDF не перенесены. Это описание
расположения сенсоров; измерения камеры, сканера и IMU оно не генерирует.

## Дефект и исправление

Сохранённые коммиты автора:

- `0278594363f46b43264ff2ad928125e42bd9869f` — исправная модель и тест родителя;
- `71a696ee71a7970230438cf308c305f8aa1d9461` — parent лидара заменён на camera_link;
- `7b073e18901b6bae3c0c092caa4e9e2c8ac52737` — восстановлен parent base_link.

При поломке изменён только parent у lidar_joint, прежний origin сохранён.
Смещение стало отсчитываться от камеры, уже смещённой относительно корпуса.
В этой модели повороты фиксированных соединений нулевые, поэтому смещения
складываются: (0.28, 0, 0.38) + (0.28, 0, 0.38) = (0.56, 0, 0.76).

| Состояние | Тест ожидаемого parent | check_urdf | base_link → lidar_link, м |
| --- | --- | --- | --- |
| Исправная исходная модель | проходит, по проверке автора | проходит | 0.28, 0, 0.38 |
| Дефект из 71a696e | падает: camera_link != base_link | проходит | 0.56, 0, 0.76 |
| После исправления | проходит | проходит | 0.28, 0, 0.38 |

Автор выполнил опыт и подтвердил исправление в переписке. Для отчёта Codex
дополнительно выгрузил ошибочную модель из сохранённого коммита во временный
каталог, запустил тот же тест и check_urdf, затем последовательно запустил
настоящий robot_state_publisher для ошибочной и исправленной моделей в отдельном
ROS_DOMAIN_ID=221. Чтение TF подтвердило оба числовых результата.
Фактический вывод сохранён в `defect-check.txt`; рабочая модель при этом не ломалась.

check_urdf проверяет допустимость структуры и не знает требуемого места установки
лидара. Ошибочная цепочка base_link → camera_link → lidar_link остаётся деревом.
Тест в `test_frames.py` дополнительно закрепляет инженерное требование: родитель
лидара должен быть base_link.

## QoS преобразований

Исходный вывод автора сохранён в `tf-qos.txt`: один издатель /tf_static,
RELIABLE и TRANSIENT_LOCAL; поздняя подписка с transient_local получила
преобразования и exit=0. Подписка с volatile не получила старую публикацию и
была остановлена timeout, exit=124. Строка `!rclpy.ok()` появилась при завершении
CLI по сигналу timeout, а не является полученным TF-сообщением.

Обе подписки совместимы с издателем. Различие — в запросе сохранённой истории.
Издатель статических преобразований хранит последнее сообщение, пока жив;
поздний transient_local-подписчик получает его. Volatile-подписчик получает
только новые публикации. /tf передаёт изменяющиеся преобразования и использует
volatile; /tf_static передаёт фиксированные и использует transient_local.

## Повтор проверки

Из корня репозитория после подключения ROS и workspace:

```bash
xacro src/course_description/urdf/ackerman_robot.urdf.xacro > /tmp/vehicle.urdf
check_urdf /tmp/vehicle.urdf
python3 -m pytest -q src/course_description/test/test_frames.py
ros2 launch course_description display.launch.py
# В другом терминале с той же средой и ROS_DOMAIN_ID:
ros2 run tf2_ros tf2_echo base_link lidar_link
ros2 run tf2_tools view_frames
```

Перед сменой версии модели следует остановить прежний launch и запустить новый:
два издателя одного статического преобразования делают результат неоднозначным.
